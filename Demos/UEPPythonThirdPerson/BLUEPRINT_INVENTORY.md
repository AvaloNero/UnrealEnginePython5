# Third Person Blueprint migration inventory

This inventory compares the unchanged Unreal Engine 5.8 Blueprint Third Person
template with the 0.2.0 Python-first runtime. Counts are generated by
`Tools/audit_template.py`; run the documented `-Mode Audit` command after an
engine/template update instead of treating these numbers as permanent API.

The current UE 5.8.0 audit loaded four Blueprint assets and found 27 graphs with
173 nodes:

| Role | Reference asset | Parent | Graphs / nodes | 0.2.0 decision |
| --- | --- | --- | ---: | --- |
| Character | `/Game/ThirdPerson/Blueprints/BP_ThirdPersonCharacter` | `Character` | 4 / 40 | Move, look, jump, camera, movement tuning and input binding move to `UEPThirdPersonCharacter` |
| Player controller | `/Game/ThirdPerson/Blueprints/BP_ThirdPersonPlayerController` | `PlayerController` | 3 / 31 | Desktop mapping-context setup moves to `UEPThirdPersonPlayerController`; mobile touch UI is outside the Win64 0.2.0 contract |
| GameMode | `/Game/ThirdPerson/Blueprints/BP_ThirdPersonGameMode` | `GameModeBase` | 2 / 1 | Class selection moves to `UEPThirdPersonGameMode` |
| Animation | `/Game/Mannequins/Anims/Unarmed/ABP_Unarmed` | `AnimInstance` | 18 / 101 | Speed/falling/landing state selection moves to Python; the mesh, blend space and clips remain assets |

The audit also loads `/Game/ThirdPerson/Lvl_ThirdPerson`. The map and its
World Partition/placed-actor data remain unchanged; a URL GameMode override
selects the Python classes at runtime. Rebuilding level data in Python would not
improve ownership or testability, so it is intentionally not a migration goal.

## Remaining Blueprint boundary

No reference Blueprint event graph owns keyboard/mouse gameplay in the
Python-first run. The assets stay in the staged project for automated comparison
and because the official map references parts of the template content set.

The sample's only project C++ is an empty primary module required to give UBT a
Game target for source-plugin packaging. It contains no character, input,
animation, map or GameMode behavior.

The retained animation content is data, not control logic:

- `SKM_Manny_Simple` supplies the skeletal mesh;
- `BS_Idle_Walk_Run` supplies pose blending;
- `MM_Jump`, `MM_Fall_Loop` and `MM_Land` supply animation clips;
- Python chooses the state and updates the blend-space position each tick.

Mobile touch controls remain in the reference PlayerController Blueprint and
are explicitly excluded from the Win64 keyboard/mouse parity gate. Networking,
replication and Lyra/Game Feature integration are later milestones rather than
hidden Blueprint dependencies of this sample.
